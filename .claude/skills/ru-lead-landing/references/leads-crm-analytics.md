# Заявки, CRM, Telegram и аналитика

Ценность лендинга для заказчика — не страница, а **заявка, которая дошла до менеджера с контекстом и источником**. Проектируй этот путь первым и проверяй его отдельным скриптом.

## 1. Путь заявки

```
LeadForm (клиент)
  → issueLeadToken() при первом фокусе — подписанная сервером метка времени
  → submitLead(prev, formData) — server action
      1. validateLead: zod + нормализация телефона в E.164; ловушка заполнена → ложный «успех», ничего не пишем
      2. checkLeadToken: подпись HMAC, не быстрее 3 с, не старше 12 ч
      3. allowRequest(hashIp(clientIp(headers))): 5 заявок за 10 минут; IP — только солёный хэш
      4. id; режим concept → ничего не сохраняем
      5. deliverLead(record, configuredSinks()): файл / Битрикс24 / 1С параллельно, успех — если сохранило хотя бы одно
      6. after(() => notifyTelegram(...)) — уведомление ПОСЛЕ ответа посетителю, без имени и телефона
      7. ответ { status: 'ok', id, smeta? } или { status: 'error', message: 'Не удалось отправить. Позвоните:' }
  → на клиенте: try/catch вокруг вызова; ok → цель lead_submit, экран успеха со следующим шагом
```

Почему так:
- **Метка времени от сервера.** Время из браузера бот подделает: при `startedAt=1` проверка «не быстрее 3 с» проходит.
- **IP — справа в `X-Forwarded-For`.** Левые элементы присылает клиент. IP = элемент № `TRUSTED_PROXY_HOPS` справа; Vercel заголовок перезаписывает целиком. Без чистки `Map` в лимите частоты подмена IP раздувает память — чисти устаревшие записи.
- **Хранилища параллельно, успех при одном.** Падение CRM не должно терять заявку, если она сохранилась в другом месте. Каждое неудачное хранилище — в журнал сервера и строкой в Telegram «не принята в …».
- **Telegram через `after()`.** Медленный `api.telegram.org` не задерживает ответ; ошибка уведомления не отменяет заявку; таймаут 5 с.
- **Без персональных данных в Telegram.** Номер, источник, вариант и ссылка на карточку в CRM — менеджер открывает заявку там.

## 2. Битрикс24

- Входящий вебхук с правом `crm`: `B24_WEBHOOK_URL=https://портал.bitrix24.ru/rest/1/ключ/` — ключ в ссылке = пароль.
- Метод `crm.item.add` (`crm.lead.add` помечен устаревшим): `entityTypeId` 1 — лид, 2 — сделка, 3 — контакт. Режим `B24_ENTITY=lead` (классический CRM) или `deal` (простой: контакт + сделка).
- Телефон — мультиполе `fm: [{ valueType: 'WORK', value: '+7…', typeId: 'PHONE' }]`; поля `title`, `sourceId` (`WEB`), `sourceDescription`, `assignedById`, комментарий — сводка заявки по строкам (источник, вариант, расчёт, ответы квиза, UTM, ClientID, версия согласия).
- Ссылка на карточку для Telegram: `https://портал/crm/lead/details/<id>/`.

## 3. 1С

Универсального API заявок у 1С нет: программист 1С публикует HTTP-сервис по контракту.
- `POST ONEC_LEADS_URL` (только https), JSON: `uid, number, createdAt, name, phone, contactMethod, comment, source, variant, context, estimate, quiz, utm, clientId, consentVersion, summary`.
- Basic-авторизация (`ONEC_USER`/`ONEC_PASSWORD`), заголовок `Idempotency-Key: uid` — повтор не создаёт вторую заявку. Ответ `{ id }`. Таймаут 8 с.
- Контракт — в `docs/INTEGRATIONS.md`, чтобы его можно было отдать программисту 1С.

## 4. Проверка интеграций

`scripts/leads-check.ts` (`pnpm leads:check`): читает env, показывает, какие каналы включены (файл, Битрикс24, 1С, Telegram), предупреждает о пропущенных секретах (`LEAD_TOKEN_SECRET`, `SMETA_SIGNING_SECRET`), спрашивает у Битрикс24 режим CRM (`crm.settings.mode.get`: 1 — с лидами, 2 — простой) и подсказывает `B24_ENTITY`. С флагом `--send` отправляет тестовую заявку во все каналы и печатает результат по каждому. Unit-тесты интеграций — с подменённым `fetch`: проверяют тело запроса и обработку ошибок.

## 5. Хранение

- На Vercel файловая система только для чтения: в `client` файл выключаем (`LEADS_FILE=off`) и сохраняем в CRM.
- Для реальных персональных данных — сервер или база в РФ (152-ФЗ, ч. 5 ст. 18), срок хранения из политики (например, один год), бэкап.
- Номер заявки «5 случайных цифр» даёт коллизии (≈ 50% к ~350 заявкам) — в базе бери последовательность.

## 6. Источник заявки

- Каждая кнопка открывает форму с `source` (`header`, `hero`, `calculator`, `quiz`, `project_modal`, `final_cta`…), заголовком = текстом кнопки и контекстом (параметры расчёта, ответы квиза).
- UTM и `yclid` сохраняются в sessionStorage при входе и уходят с заявкой. Лучше — первое и последнее касание на 90 дней (в политике cookie это нужно упомянуть).

## 7. Яндекс Метрика

- `NEXT_PUBLIC_METRIKA_ID` → `SITE.metrikaId` (не секрет). Счётчик подключается `next/script` **только после «Принять все»** в баннере cookie; Вебвизор выключен (он записывает ввод в формы).
- Параметр визита `variant` — для сравнения кампаний.
- `track(goal, params)` — тонкая обёртка над `ym(id, 'reachGoal', …)`, без счётчика ничего не делает. В параметрах нет персональных данных.
- Цели (тип «JavaScript-событие»):

| Цель | Когда |
|---|---|
| `lead_submit` | Сервер принял заявку (`source`, `variant`) |
| `calc_interact` | Первое изменение в калькуляторе за визит |
| `quiz_start` / `quiz_complete` | Первый ответ / показана вилка |
| `pdf_download` | Скачана смета или образец |
| `phone_click` | Клик по `tel:` |
| `messenger_click` | Клик по мессенджеру (`channel`) |
| `project_open` / `case_open` | Открыто окно (`slug`), в том числе по ссылке |
| `excursion_click` | Кнопка экскурсии |

- Клики по `tel:`, `.pdf`, `/smeta/` и `[data-messenger]` ловит **один делегированный обработчик** на документе: новая кнопка получает цель без правок кода.
- `ym(id, 'getClientID', cb)` с таймаутом → скрытое поле формы → CRM. По ClientID в Метрику загружаются офлайн-конверсии (квалифицирован, встреча, договор), и Директ учится на заявках, которые дошли до продажи.
- e2e: заглушка `window.ym` собирает вызовы, тест проверяет цели и параметры.
- Пока заявок мало, Директ лучше обучать на составной цели вовлечённости (открыл проект, изменил калькулятор, прошёл квиз, скачал PDF).

## 8. Согласие на cookie

- Баннер с равнозначными кнопками «Принять все» / «Только необходимые»; выбор — в `localStorage` с запасной копией в памяти страницы (приватный режим); `useSyncExternalStore` для чтения.
- До выбора и при «только необходимые» — никаких сторонних запросов (Метрика, Яндекс Карты); e2e проверяет отсутствие запросов к `yandex.ru`/`mc.yandex.ru`.
- «Настройки cookie» в футере стирают выбор — баннер появляется снова.
- Тексты баннера и `/cookies` упоминают Метрику, только когда номер счётчика задан.

## 9. Мессенджеры

- Прямые ссылки в `SITE.messengers` (Telegram `https://t.me/…`, MAX — ссылка-приглашение). Пусто — кнопки открывают форму с выбранным способом связи.
- WhatsApp и Telegram — иностранные сервисы: передача туда телефона клиента требует оценки юриста (152-ФЗ, ст. 12).
