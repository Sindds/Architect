# Замеры качества

## Скорость на телефоне — 12.10.2026

> Замеры от 12.10.2026, до замены картинок 18.10 и SEO 19.10 — перемерить перед сдачей.

Lighthouse 13.5, мобильный профиль, Chromium 141 headless, `benchmarkIndex` ≈ 2100 (сопоставимо с машинами PageSpeed Insights). Production-сборка (`pnpm build && pnpm start`). На каждую строку 5 прогонов: медиана, в скобках разброс LCP. «До» — коммит `c41388c`, «после» — коммит с задачей P8.2.

| Условия | Версия | Оценка | LCP, с | FCP, с | TBT, мс | Вес, КБ | CLS |
|---|---|---|---|---|---|---|---|
| HTTP/2, `simulate` (как PageSpeed Insights) | до | 93 | 2,93 (2,71–4,11) | 1,81 | 103 | 588 | 0 |
| | **после** | **97** | **2,41 (2,25–2,79)** | **1,51** | **52** | **374** | 0 |
| HTTP/2, `devtools` (сеть и процессор замедляются на самом деле) | до | 75 | 2,32 (2,25–2,67) | 1,79 | 909 | 623 | 0 |
| | **после** | **92** | **1,57 (1,53–1,60)** | **1,49** | **310** | **374** | 0 |
| HTTP/1.1 локального `next start`, `simulate` | до | 88 | 3,55 (2,96–4,68) | 1,97 | 91 | 595 | 0 |
| | после | 91 | 3,34 (2,73–3,36) | 1,66 | 63 | 382 | 0 |

Остальные категории после: доступность 100, рекомендации 100. SEO 69 на момент замера — только из-за `noindex`. С 19.10.2026 индексация открыта, поэтому оценку SEO нужно замерить заново.

**Порог.** Google считает LCP хорошим, если он не больше 2,5 с у 75 % посещений, отдельно для телефонов и компьютеров ([web.dev/articles/lcp](https://web.dev/articles/lcp)). Это полевые данные реальных людей. Лабораторный замер — ориентир.

**Почему главная строка — HTTP/2.** Vercel отдаёт сайт по HTTP/2 (ответ в [сообществе Vercel](https://community.vercel.com/t/vercel-custom-domain-serving-http-1-1-instead-of-http-2-with-missing-compression/38564/5); в официальной документации отдельной строки нет). Проверить на развёрнутом сайте: DevTools → Network → колонка Protocol = `h2`. По HTTP/1.1 Lighthouse моделирует несколько соединений, у каждого своё рукопожатие и «медленный старт», и завышает время.

**Почему у `simulate` разброс.** Этот режим считает загрузку по прогону без замедления ([документация Lighthouse](https://github.com/GoogleChrome/lighthouse/blob/main/docs/throttling.md): Slow 4G — 1,6 Мбит/с, задержка 150 мс, процессор ×4). Если в этом прогоне React начал гидратацию на несколько миллисекунд раньше, чем кадр с фото попал на экран, модель включает всю гидратацию в LCP. Получается 2,7–2,8 с вместо 2,25 с. При настоящем замедлении (`devtools`) такого скачка нет.

### Что дало ускорение

| Изменение | Эффект |
|---|---|
| Шрифты: один файл-подмножество на семейство вместо трёх срезов (`scripts/subset-fonts.py`), толщины 400–700, без предзагрузки | 9 файлов ≈ 200 КБ → 3 файла ≈ 72 КБ. CSS первого экрана больше не делит канал со шрифтами. Запасной шрифт с подогнанными метриками: CLS 0 |
| Блоки ниже первого экрана — `content-visibility: auto` (`.lazy-section`) | Первый пересчёт стилей и раскладка — только у первого экрана. Переход по якорю раскладывает страницу целиком (`src/lib/lazy-sections.ts`) и встаёт точно на блок (тест в `performance.spec.ts`) |
| zod не попадает в браузер (`src/lib/lead-constants.ts`), окна проекта и заявки — `next/dynamic` | JS первой загрузки: 279 → 188 КБ gzip (бюджет плана ≤ 200 КБ; legacy — 343 КБ) |
| Фото первого экрана: качество 70 вместо 75 (`images.qualities`, раньше 70 молча заменялось на 75) | AVIF 750 px: 36,6 → 29,9 КБ |

### Как повторить

```bash
pnpm build && pnpm start                     # :3100
mkdir -p .h2 && openssl req -x509 -newkey rsa:2048 -nodes -keyout .h2/key.pem -out .h2/cert.pem -days 2 -subj "/CN=localhost"
node scripts/h2-proxy.mjs                    # https://localhost:3443
npx lighthouse@13.5.0 https://localhost:3443/ --output=json --output-path=m1.json \
  --chrome-flags="--headless=new --no-sandbox --ignore-certificate-errors"
# режим с настоящим замедлением: добавить --throttling-method=devtools
```

На развёрнутом сайте: [pagespeed.web.dev](https://pagespeed.web.dev) → вкладка «Мобильные устройства». Запустите 3–5 раз: разброс между прогонами — норма для лабораторного замера.
