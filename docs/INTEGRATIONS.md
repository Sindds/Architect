# Заявки: Telegram, Битрикс24, 1С

Заготовки рабочие: каналы включаются серверными переменными окружения, код менять не нужно.
Работают только в режиме `client` (`SITE.contentMode`). В режиме `concept` персональные данные никуда не уходят.

## Как идёт заявка

1. Форма → server action `submitLead` (`src/app/actions/lead.ts`): проверка, ловушка для ботов, лимит частоты.
2. Заявка уходит **параллельно** во все включённые хранилища (`src/lib/leads/deliver.ts`):
   - файл `.data/leads.ndjson` на сервере (по умолчанию включён, `LEADS_FILE=off` выключает);
   - Битрикс24 — если задан `B24_WEBHOOK_URL`;
   - 1С — если задан `ONEC_LEADS_URL`.
3. Заявка принята, если её сохранило **хотя бы одно** хранилище. Если не сохранило ни одно, посетитель видит «Не удалось отправить» и телефон.
4. После ответа посетителю в Telegram уходит уведомление: номер заявки, источник, вариант, ссылка на карточку в Битрикс24 и номер в 1С. Если какое-то хранилище не приняло заявку, в уведомлении есть строка «Не принята в …».
   **Имени и телефона в Telegram нет** (152-ФЗ, правило 7 CLAUDE.md): менеджер открывает их по ссылке в CRM.

Ошибки хранилищ пишутся в журнал сервера (`[lead] №… не принята: bitrix24 …`).

## Переменные окружения

Только на сервере, без префикса `NEXT_PUBLIC_`. Локально — файл `.env.local`, на хостинге — его настройки.

| Переменная | Что это | Пример |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather | `123456:ABC…` |
| `TELEGRAM_CHAT_ID` | Чат или группа менеджеров | `-1001234567890` |
| `B24_WEBHOOK_URL` | Входящий вебхук Битрикс24 с правом CRM | `https://arcline.bitrix24.ru/rest/1/abc123/` |
| `B24_ENTITY` | `lead` — классический режим CRM, `deal` — простой (контакт + сделка). По умолчанию `lead` | `lead` |
| `B24_ASSIGNED_BY_ID` | Ответственный: ID пользователя Битрикс24 (необязательно) | `12` |
| `B24_SOURCE_ID` | Источник в CRM (необязательно, по умолчанию `WEB`) | `WEB` |
| `ONEC_LEADS_URL` | HTTP-сервис 1С, принимающий заявки | `https://1c.arcline.ru/base/hs/leads/v1/leads` |
| `ONEC_USER`, `ONEC_PASSWORD` | Пользователь 1С для Basic-авторизации | |
| `LEADS_FILE` | `off` — не писать заявки в файл (на Vercel запись в файл не работает) | `on` |

Адреса Битрикс24 и 1С принимаются только `https`.

## Проверка настроек

```bash
pnpm leads:check          # ничего не отправляет: какие каналы включены и какой режим CRM в портале
pnpm leads:check --send   # тестовая заявка «Проверка интеграции» в Битрикс24 и 1С + уведомление в Telegram
```

Тестовую заявку потом удалите в CRM. Если `leads:check` пишет «Поставьте B24_ENTITY=deal», в портале выключены лиды.

## Telegram

1. В @BotFather: `/newbot` → получите токен (`TELEGRAM_BOT_TOKEN`).
2. Добавьте бота в группу менеджеров и напишите в группе любое сообщение.
3. Откройте `https://api.telegram.org/bot<токен>/getUpdates` и возьмите `chat.id` (`TELEGRAM_CHAT_ID`).

Доступность `api.telegram.org` с российского сервера проверьте отдельно. Если её нет, уведомления не придут, а заявки всё равно сохранятся.

## Битрикс24

Используется метод `crm.item.add`. Метод `crm.lead.add` в документации помечен устаревшим: «Развитие метода остановлено. Используйте crm.item.add» ([apidocs.bitrix24.ru](https://apidocs.bitrix24.ru/api-reference/crm/leads/crm-lead-add.html)).

1. В портале создайте **входящий вебхук** с правом **CRM (crm)**. Ссылка вида `https://портал/rest/{ID пользователя}/{ключ}/` → `B24_WEBHOOK_URL`. Ключ — это пароль: никому не пересылайте.
2. Узнайте режим CRM: `pnpm leads:check` (метод `crm.settings.mode.get`: 1 — классический, 2 — простой). В простом режиме поставьте `B24_ENTITY=deal`.
3. Что создаётся:
   - `lead`: лид (`entityTypeId: 1`) — название «Заявка №… с сайта», имя, телефон (`fm`, тип `PHONE`), источник, UTM-метки, комментарий со всеми ответами формы, калькулятора и квиза;
   - `deal`: контакт (`entityTypeId: 3`) с именем и телефоном, затем сделка (`entityTypeId: 2`) с теми же полями и ссылкой на контакт.
4. Ответственный — `B24_ASSIGNED_BY_ID`. Без него Битрикс24 назначит владельца вебхука.

Поля сверены с [описанием полей CRM-объектов](https://apidocs.bitrix24.com/api-reference/crm/universal/object-fields.html) и [crm.item.add](https://apidocs.bitrix24.ru/api-reference/crm/universal/crm-item-add.html). На живом портале интеграция ещё не проверялась: сделайте `pnpm leads:check --send` после настройки.

Дубли контактов в режиме `deal` не ищутся: используйте контроль дублей в самом Битрикс24.

## 1С

Готового API заявок у 1С:Предприятия нет, поэтому сайт отправляет заявку в **HTTP-сервис** базы. Сервис пишет программист 1С под вашу конфигурацию (1С:CRM, УНФ, своя база) по контракту ниже.

### Запрос

`POST {ONEC_LEADS_URL}`

Заголовки:
- `Content-Type: application/json; charset=utf-8`
- `Authorization: Basic …` — если заданы `ONEC_USER` и `ONEC_PASSWORD`
- `Idempotency-Key: {uid}` — тот же, что `uid` в теле

Тело:

```json
{
  "uid": "1b9d6bcd-bbfd-4b2d-9b5d-ab8dfbbd4bed",
  "number": 48213,
  "createdAt": "2026-10-10T10:00:00.000Z",
  "name": "Анна",
  "phone": "+79161234567",
  "contactMethod": "telegram",
  "contactMethodLabel": "Telegram",
  "comment": "Участок 15 соток",
  "source": "quiz",
  "sourceLabel": "квиз",
  "variant": "monolith",
  "context": null,
  "estimate": null,
  "quiz": "Площадь: 200–250 м²",
  "utm": { "utm_source": "yandex", "utm_campaign": "monolith", "yclid": "123" },
  "consentVersion": "1.0",
  "summary": "Заявка №48213 с сайта\nИсточник: квиз…"
}
```

`phone` всегда в формате E.164 (`+7` и 10 цифр). Необязательные поля приходят как `null`.

### Ответ

- `200` или `201` и JSON `{ "id": "номер документа в 1С" }`. Номер попадёт в уведомление в Telegram.
- Повтор с тем же `uid` не создаёт новую заявку: верните `200` и тот же `id`.
- Любой другой код — сайт считает, что 1С заявку не приняла, и пишет об этом в журнал и в Telegram.
- Время ответа — до 8 секунд, дальше сайт прерывает запрос.

## Перед включением: 152-ФЗ

- **Тексты согласия и политики.** Сейчас в согласии написано «Без передачи третьим лицам» (`src/content/legal.ts`), а в политике — «хранятся в базе данных на сервере в России». С включённой CRM данные передаются обработчику: Битрикс24 и/или серверу 1С. Юрист должен перечислить их в согласии и политике **до** включения интеграций.
- **Где хранятся данные.** Сервер сайта, портал Битрикс24 и сервер 1С должны хранить персональные данные в России (ч. 5 ст. 18 152-ФЗ). Где находится ваш портал Битрикс24, уточните у Битрикс24.
- **Договор-поручение** с каждым обработчиком (ч. 3 ст. 6 152-ФЗ).
- В Telegram персональные данные не передаются, это проверяет юнит-тест (`tests/unit/integrations.test.ts`).
