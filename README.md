# ARCLINE — лендинг архитектурно-строительного бюро

Одностраничный лендинг бюро ARCLINE ESTATE: дома из клееного бруса и монолита с панорамным остеклением в Подмосковье. Готовый шаблон под заказчика: рабочие заявки (почта, Битрикс24, 1С, файл на сервере, уведомления в Telegram), открытая индексация и SEO для Яндекса, Google и ИИ-ассистентов. Данные компании в шаблоне — заглушки (`+7 (000) 000-00-00`, ИНН из нулей, `example.com`): под заказчика их меняют по разделу «Под нового заказчика».

## Под нового заказчика

Всё, что меняется под заказчика, — в папке `src/content/`, карта «что где» — `src/content/README.md`.

1. **Данные компании — один файл `src/content/company.ts`**: название, телефон, почта, адрес и точка на карте, часы, ссылки на Telegram, MAX, ВКонтакте и WhatsApp, реквизиты, обработчики данных. Поля с пометкой «ЗАМЕНИТЬ» в шаблоне — заглушки.
2. **Тексты — `src/content/texts.ts`**: все надписи страницы по блокам (меню, заголовки, кнопки, формы, квиз, калькулятор, этапы, вопросы, футер). Проекты — `projects.ts`, команда и отзывы — `people.ts`, цены и пакеты — `pricing.ts`.
3. **Картинки — папка `src/content/images/`**: новый файл под тем же именем заменяет старый, подписи — `media.ts`.
4. **Пересобрать файлы**: `pnpm map:preview` (карта), `pnpm docs:pdf` (образцы договора и сметы), `pnpm seo:images` (значки и картинка для соцсетей).
5. **Проверить**: `pnpm ready` — что ещё не заполнено и не настроено для публикации; `pnpm check`, `pnpm build`, `pnpm e2e`. Юридические тексты перед запуском читает юрист заказчика, оператор подаёт уведомление в Роскомнадзор (`docs/COMPLIANCE.md`).
6. **Опубликовать** — раздел «Публикация» ниже.

## Публикация

Заявки доходят до менеджера только через подключённый канал: почту, Битрикс24 или 1С. Без него форма показывает «Не удалось отправить. Позвоните: …». На Vercel файл заявок на сервере не работает: там нельзя записывать файлы.

**Vercel**

1. `pnpm env:init` — создаст `.env.local` с ключами защиты формы (`LEAD_TOKEN_SECRET`, `SMETA_SIGNING_SECRET`, `RATE_LIMIT_SALT`). Шаблон со всеми переменными и подсказками, где их взять, — `docs/env.example`.
2. Впишите в `.env.local` почту для заявок. Пример для Яндекс 360: `SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465`, `SMTP_USER` — адрес ящика, `SMTP_PASS` — пароль приложения (id.yandex.ru → Безопасность → Пароли приложений), `LEADS_EMAIL_TO` — кому слать. Или Битрикс24: `B24_WEBHOOK_URL`. Подробно — `docs/INTEGRATIONS.md`.
3. Проверьте: `pnpm leads:check` (вход на почтовый сервер), `pnpm leads:check --send` (тестовая заявка), `pnpm ready`.
4. Vercel → проект → Settings → Environment Variables: добавьте переменные из `.env.local` и `NEXT_PUBLIC_SITE_URL` (адрес сайта, например `https://arcline.ru`). Затем Deployments → последний деплой → Redeploy: переменные применяются только к новой сборке.
5. Отправьте заявку с сайта и убедитесь, что письмо пришло. Если чего-то не хватает, сборка на Vercel пишет предупреждение «⚠ Заявки: …» в журнал (Deployments → Build Logs).

**Сервер в России** (152-ФЗ, ч. 5 ст. 18: данные граждан РФ первично хранятся в РФ — `docs/COMPLIANCE.md`): Node 20.9+, `pnpm install --frozen-lockfile && pnpm build && pnpm start`, переменные — в `.env.local` или в окружении процесса, перед сайтом — nginx или Caddy с HTTPS. Здесь работает и файл заявок (`LEADS_DIR` — постоянная папка).

Контент, цифры и запреты — `docs/CONTENT-SPEC.md`. Исходный прототип — `legacy/` (только для чтения).

## Запуск

Нужны Node 20.9+ и pnpm.

```bash
pnpm install
pnpm dev            # http://localhost:3000
pnpm build && pnpm start
```

Проверки:

```bash
pnpm check          # typecheck + eslint + lint:content + unit-тесты
pnpm e2e            # Playwright: 390 px и 1440 px, axe; перед запуском — pnpm build
pnpm docs:pdf       # пересобрать PDF-образцы договора и сметы в public/docs (тексты — scripts/sample-docs.ts)
```

Playwright берёт Chromium из `CHROMIUM_PATH`, затем из `/opt/pw-browsers/chromium` (облачный контейнер), иначе — свой браузер: поставьте его командой `pnpm exec playwright install chromium`.

## Дизайн, темы и лоадер

- Дизайн по образцу architectural-three.vercel.app: bento-карточки, крупные скругления, тёмный первый экран с фото, заголовки прописными, кнопки-капсулы, стальной синий акцент. Шрифты с кириллицей: Onest (текст), Manrope (заголовки), JetBrains Mono (метки).
- Светлая и тёмная тема: по умолчанию как в системе, переключатель в шапке, выбор запоминается. Тему выставляет скрипт в `<head>` до отрисовки, поэтому страница не мигает. Цвета обеих тем проходят WCAG AA (проверяет `tests/unit/theme.test.ts`).
- Лоадер в стиле образца показывается один раз за сессию. Полоса отражает настоящую загрузку (шрифты, фото первого экрана), лоадер длится не дольше 1,4 с плюс затухание. При `prefers-reduced-motion` его нет; если JS не загрузился, CSS убирает лоадер через 2,2 с. Весь текст страницы при этом уже есть в HTML.

## Что на странице

Порядок блоков — `CONTENT-SPEC.md` §4: шапка → первый экран → как мы работаем → проекты → цены → калькулятор и квиз → как строим → команда → отзывы → документы → вопросы → контакты → футер.

- **Окна проектов** открываются по ссылке `/?project=vista`. Блока «Кейсы», списка сданных домов и их окон нет (решение заказчика 17.10.2026). Esc и «Назад» в браузере закрывают окно.
- **Калькулятор** считает по тем же ставкам, что карточки и окна. `/?calc=titan#calculator` подставляет параметры проекта.
- **Квиз** — 4 вопроса и вилка цены, затем форма.
- **Варианты под рекламу**: `/?v=fachwerk`, `/?v=monolith`, `/?v=scandi` или `utm_content=…` — свой H1 и первый проект уже в HTML, без подмены в браузере. Canonical — `/`.
- **Заявки**: Server Action с проверкой полей (zod), ловушкой для ботов, минимальным временем заполнения и лимитом 5 заявок за 10 минут с одного IP.
- **Юридические страницы**: `/privacy`, `/soglasie`, `/cookies` (собираются из `SITE`, проверяет юрист заказчика) и 404.
- **SEO**: открытая индексация; `robots.txt` с `Clean-param` для Яндекса (рекламные метки и окна не плодят дубли); `sitemap.xml` с картинками проектов; canonical, Open Graph и картинка 1200×630 для соцсетей; разметка schema.org (подрядчик с адресом, часами и ценами, каталог услуг, проекты с ценами, вопросы и ответы) — `src/lib/seo.ts`; `llms.txt` — сводка сайта для ИИ-ассистентов (Алиса, YandexGPT, ChatGPT, Perplexity) из того же контента; значки и манифест. Личные сметы `/smeta/…` закрыты от индексации.
- **Баннер cookie** при первом входе: «Принять все» или «Только необходимые» (`src/lib/consent.ts`). Яндекс Карта в футере грузится только после «Принять все» или по кнопке «Показать карту».
- **Яндекс Метрика**: счётчик из `NEXT_PUBLIC_METRIKA_ID`, только после «Принять все», Вебвизор выключен. Цели (`lead_submit`, `calc_interact`, `quiz_start`, `quiz_complete`, `pdf_download`, `phone_click`, `messenger_click`, `project_open`), параметр визита `variant`, ClientID в заявке — `docs/ADMIN-GUIDE.md`.
- **Смета в PDF после заявки**: «Получить смету в PDF» в калькуляторе, карточках пакетов и окне проекта передаёт параметры дома; после заявки — «Скачать смету (PDF)» по ссылке `/smeta/<токен>` (HMAC, 7 дней, `SMETA_SIGNING_SECRET`). PDF собирает `src/lib/smeta-pdf.tsx` (@react-pdf/renderer, шрифты из `scripts/pdf-fonts`), персональных данных в нём нет.
- **Образцы документов**: договор строительного подряда (17 разделов и график платежей) и смета (83 позиции в 14 разделах, итог считает `estimateFor` в `src/lib/pricing.ts`). Шрифты PDF — статические TrueType из `scripts/pdf-fonts`: вариативные Chrome встраивает как Type 3, и они ломаются в просмотрщиках.

## Заявки

- Заявка уходит параллельно во все настроенные хранилища: почту (имя, телефон и все параметры — письмом менеджерам), Битрикс24, 1С и файл `leads.ndjson` на сервере (на Vercel файл выключен). Принята, если её сохранило хотя бы одно; иначе посетитель видит телефон.
- Ключи защиты формы `LEAD_TOKEN_SECRET` и `SMETA_SIGNING_SECRET` обязательны: `pnpm env:init` создаёт их сам.
- В Telegram — номер заявки, источник, вариант и ссылка на карточку в CRM, без имени и телефона.
- Настройка каналов, контракт для 1С и проверка `pnpm leads:check [--send]` — `docs/INTEGRATIONS.md`.

## Что из `docs/PLAN.md` пока не сделано

Сделана упрощённая версия без CMS. Не реализовано:

- админка Payload CMS и Postgres (контент сейчас в `src/content/*.ts`, структура повторяет будущие коллекции);
- проверка передачи заявок на живом портале Битрикс24 и в базе 1С: код и тесты с подменой API есть (`src/lib/leads/`, `pnpm leads:check`), настоящих ключей нет;
- A/B-тест заголовка;
- Docker и инструкция по деплою (`docs/DEPLOY.md`). Замер скорости — `docs/QA.md`.

## Стек

Next.js 16.3 (App Router, статическая генерация) · React 19 · TypeScript strict · Tailwind CSS 4 · zod · Vitest · Playwright + axe.
