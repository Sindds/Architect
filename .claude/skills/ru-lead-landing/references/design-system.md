# Дизайн-система и интерфейс

## 1. Направление

- Если установлен скилл `ui-ux-pro-max` — используй его поиск по доменам (`--domain ux`, `--stack nextjs`) для спорных решений и сверяйся с его чек-листом. Результаты поиска — рекомендации, а не приказ: сверяй с продуктом.
- Выбери одно ясное направление и держи его везде. Для премиальных услуг хорошо работают: тёмный первый экран с фото на всю ширину, bento-сетка карточек, капсульные кнопки, спокойная типографика с крупными заголовками.
- Избегай шаблонного «ИИ-вида»: фиолетовые градиенты на белом, Inter/Roboto/Arial, одинаковые карточки с иконками-эмодзи.

## 2. Токены и темы

- Цвета — CSS-переменные `--c-*` в `globals.css` для светлой и тёмной темы; Tailwind 4 читает их через `@theme` (`--color-bg: var(--c-bg)`). В компонентах — только токены, не hex: так тест контраста видит все цвета.
- Тема ставится inline-скриптом в `<head>` до первой отрисовки (`localStorage` → `prefers-color-scheme`), чтобы не было вспышки. Скрипт без импортов, всё в `try`.
- Тест контраста (`theme.test.ts`): пары текст/фон ≥ 4,5:1 для обеих тем.
- Тёмные блоки (`.on-dark`) переопределяют цвет фокуса, чтобы кольцо было видно.

## 3. Шрифты

- Только шрифты с кириллицей (проверь подмножество `cyrillic`). Хорошо показали себя: Onest (текст), Manrope (заголовки), JetBrains Mono (метки).
- Локальные файлы через `next/font/local`, **один файл-подмножество на семейство**: кириллица + базовая латиница + знаки (₽ U+20BD, № U+2116, «», —, стрелки), толщины только используемые (например, 400–700). Срезы Google Fonts по `unicode-range` тянут файл latin-ext на 28 КБ ради одного «₽».
- Сборка подмножества — `fontTools` (`subset` → потом `instancer` по оси `wght`; в обратном порядке падает на ленивой `gvar`). Скрипт кладём в репозиторий (`scripts/subset-fonts.py`) с версиями и ссылками на исходники.
- Без `preload`, `display: swap`, `adjustFontFallback: 'Arial'` для текстовых — CLS остаётся 0, а CSS первого экрана не делит канал со шрифтами.
- e2e-тест: каждый символ видимого текста главной и юридических страниц входит в набор символов подмножества.

## 4. Мобильные правила

- Цели нажатия ≥ 44×44 px (WCAG 2.2, 2.5.8 — минимум 24, но для телефона берём 44), расстояние между ними ≥ 8 px.
- **Нет горизонтальных лент прокрутки**: карточки идут столбиком; тест проверяет `scrollWidth` страницы и каждого блока на 320–1440 px.
- **Размытие фона (`backdrop-filter`) только для мыши**: вариант Tailwind `fine:` или `@media (hover: hover) and (pointer: fine)`. На сенсорных экранах — плотный фон: размытие в разы удорожает кадр при прокрутке на Android.
- Шапка фиксированная, компактная; на телефоне: логотип, телефон, мессенджер, тема, меню.
- **Нижняя кнопка на телефоне** — одна компактная капсула «Рассчитать стоимость» справа (≈ 236×46 px, ~3% экрана), без дублей звонка и мессенджера, которые уже есть в шапке. Прячется на первом экране, у калькулятора (там своя панель итога), в контактах и пока виден баннер cookie. Скрытая — `invisible` + `inert`, иначе её найдут скринридер и `getByRole`. Учитывай `env(safe-area-inset-bottom)`.
- `.sr-only` внутри контейнера с `overflow-x-auto` клади в `relative`-родителя, иначе он расширяет страницу.

## 5. Анимации

- **Элемент LCP (фото первого экрана) не анимируем**: `loading="eager"`, `fetchPriority="high"`, без появления.
- Появление блоков `.reveal` в обе стороны прокрутки: inline-скрипт в `<head>` с IntersectionObserver ставит `data-in` и `data-from` (`top`/`bottom`), CSS-переходы только `transform` и `opacity` без 3D (вход ~650 мс, выход ~350 мс, шаг в группе 45 мс через `--i`). Новые узлы подхватывает MutationObserver. Без JS и при `prefers-reduced-motion` атрибута нет — всё видно сразу.
- **`.reveal` и `.card-hover` на одном элементе не ставить**: правило появления перебивает `transform` ховера. Появление — на `<li>`, ховер — на карточку внутри.
- Ховер заметный: подъём ~8 px, лёгкое увеличение, тень, акцентная рамка, увеличение фото 1.06; нажатие `scale(.985)`. Только для мыши.
- Никаких анимаций, привязанных к прокрутке (`animation-timeline`), на телефоне: они держат слои на GPU всё время жизни страницы. Тест: ≤ 15 GPU-слоёв после прокрутки.
- `prefers-reduced-motion`: переходы выключены, плавная прокрутка выключена.

## 6. Лоадер

Если заказчик настаивает на прелоадере: один раз за сессию, без фейкового прогресса, не показывается при reduced motion и рекламному трафику, без JS исчезает сам (CSS-анимация), длительность ≤ 1,4 с. Решение фиксируй в журнале решений.

## 7. Окна и формы

- Окна — нативный `<dialog>` (фокус-ловушка и Esc из коробки), ссылка на окно в адресе (`/?project=slug`), «Назад» закрывает окно.
- Форма: подпись связана с полем, ошибки рядом с полем через `aria-describedby`, `aria-invalid`; маска телефона, которая не мешает удалять символы; согласие на ПДн — отдельный чекбокс, по умолчанию не отмечен.
- После отправки — экран успеха со следующим шагом (скачать смету, написать в мессенджер), а не тупик.

## 8. Карта и сторонние виджеты

Яндекс Карта — только после согласия на cookie или клика: до этого статичная картинка (превью из OSM с атрибуцией) и кнопка «Интерактивная карта». Атрибуция OSM — ссылкой под картой (цель ≥ 44 px).
