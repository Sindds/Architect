# Тестирование

Тесты здесь — не формальность: они держат правила проекта (цены из одного модуля, тексты без клише, доступность, мобильная вёрстка), которые иначе тихо ломаются при каждой правке.

## 1. Команды

`pnpm check` = `typecheck` (`next typegen && tsc --noEmit`) + `lint` + `lint:content` + `test` (Vitest). Отдельно `pnpm e2e` (Playwright) на production-сборке: `pnpm build` → тесты сами поднимут `pnpm start` или переиспользуют запущенный сервер.

Перед каждым коммитом — `pnpm check`. Перед пушем значимой правки — полный `pnpm e2e`. В отчёте — итог: «145 unit, 203 e2e прошли, 3 пропущены по условию».

## 3. e2e (Playwright)

Конфиг: два проекта — `mobile` (Pixel 7, 390×844) и `desktop` (1440×900), `locale: 'ru-RU'`, сервер `pnpm start --port 3100`, `reuseExistingServer: true`. В облачном контейнере Chromium — `/opt/pw-browsers/chromium` (`executablePath`).

Фикстура `page`:
- выключает лоадер (ключ в `sessionStorage`) и баннер cookie (выбор «необходимые» в `localStorage`) — отдельные тесты проверяют их явно;
- **даёт каждому тесту свой IP** (`x-forwarded-for` из хэша `testId`): иначе лимит «5 заявок за 10 минут» роняет тесты в зависимости от порядка.

| Спека | Что проверяет |
|---|---|
| `landing.spec.ts` | H1 с ценой в исходном HTML; варианты отдают свой H1; цена в H1 ≤ минимальной цены в карточках; окна по `?project=`; формы и PDF-смета; ошибка сервера и обрыв сети (`page.route` → abort/500) показывают телефон, а не падение; кнопки ведут куда обещают; axe WCAG 2.2 AA (`wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa`) без serious/critical на `/`, в окне, на юр. странице в обеих темах; весь видимый текст — в наборе символов шрифтов |
| `responsive.spec.ts` | 320–1440 px: H1 не длиннее N строк, цена в одну строку, шапка в одну строку, плитки не переполнены, нет горизонтальной прокрутки у страницы и блоков, видимый текст кнопок входит в доступное имя |
| `performance.spec.ts` | На сенсорном экране нет `backdrop-filter`, нет `animation-timeline`, ≤ 15 GPU-слоёв после прокрутки (CDP `LayerTree`); появление в обе стороны; reduced motion; ленивые блоки и точный переход по якорю |
| `consent.spec.ts` | До согласия нет запросов к Яндексу; карта после согласия или клика; «Настройки cookie» возвращают баннер; нижняя кнопка не перекрывает баннер |
| `analytics.spec.ts` | Заглушка `window.ym` собирает вызовы: цели и параметры, ClientID в заявке |
| `design.spec.ts` | Визуальные решения дизайн-системы (капсулы, скругления, шрифт заголовков с кириллицей), тема по системе и переключатель, скрипт темы в `<head>`, axe в тёмной теме; лоадер — один раз за сессию, не для рекламы, не при reduced motion |

## 4. Правила хороших тестов

- **Проверь, что тест ловит регрессию.** После исправления временно отключи его (например, `page.addInitScript` с CSS, возвращающим старое поведение, или копия спеки с правкой) и убедись, что тест падает. Так тест на точный переход по якорю упал на 943 px без исправления.
- Тест должен проверять поведение пользователя, а не детали разметки: `getByRole`, `getByTestId` для ключевых узлов, доступные имена.
- Неразрывные пробелы: перед сравнением текста заменяй ` ` на пробел.
- Не жди фиксированное время там, где можно ждать состояние (`expect.poll`, `toHaveAttribute`). Для плавной прокрутки — жди, пока `scrollY` не меняется ~500 мс.
- Скрытые элементы (`invisible` + `inert`) не находит `getByRole`; проверяй атрибут состояния (`data-shown`).
- Плавная прокрутка из теста (`scrollTo` при `scroll-behavior: smooth`) может наложиться на следующий клик: перезагружай страницу или прокручивай с `behavior: 'instant'`.
- Перед прогоном всего e2e убедись, что сервер запущен на свежей сборке: `reuseExistingServer` подхватит старый.

## 5. Ручные проверки, которые тесты не заменяют

- Открой на реальном телефоне (через туннель или деплой), пролистай всю страницу, отправь заявку.
- Отправь тестовую заявку в настоящую CRM (`pnpm leads:check --send`) и проверь карточку и Telegram.
- Скриншоты 390 px первого экрана, формы, окна, футера — посмотри глазами.
